# Admitted designer inputs

HTTP runs, every member of a sweep, optimization evaluations, and mesh-convergence refinements use the declarative `.design.json` admitted for that request. Parameter defaults/limits, checks and saved-design previews consume that same read. Admission reads UTF-8 bytes without newline normalization; each queued job stores the text under its own `input/<original filename>`. `job.json` retains the original model path/identity and adds `input_snapshot` with format, original basename, model ID and SHA256 of the exact admitted bytes. Result names, parameter overrides and optimization source basename retain their existing meaning.

Before launching any child, the queue checks the fixed job-local input directory, basename containment, identity and hash. Missing/altered snapshots fail the job without launching it; they never fall back to the current source. Snapshot paths supplied in job metadata are ignored. Cancellation remains the existing queue/process mechanism. History retains snapshot provenance; queued/running jobs after restart remain interrupted under the existing policy, rather than automatically replaying.

Convergence stores the same admitted text in its private study `job_kw`; later densities receive it even if the original file changes. All geometry planning inside run/optimization children uses the snapshot. For a single HTTP designer run, the existing admission geometry/check pass now builds the admitted text with the exact validated parameter overrides. Its server-owned positive integer mesh count drives memory preflight and Auto threads; client cell counts/hashes cannot replace it. The response preflight records the cells, admitted-input SHA256 and overrides. A failed/timed-out build or unavailable cell count prevents queueing instead of falling back to a client estimate.

Batch HTTP admission (sweeps, optimization, convergence) and Python models retain their advisory client estimates. Every actual solve, including each batch member/evaluation, independently checks the built mesh against current free memory at `Simulation.run` immediately before the solver boundary. That runtime guard remains authoritative: an admission estimate is not a reservation of memory or a bound on arbitrary optimization geometry.

Python model files and their imports are not copied or relocated. Legacy jobs and direct embedded `JobManager.submit` callers that omit `design_input` keep their original mutable-path behavior. Custom command factories are hash-checked for admitted jobs but remain responsible for actually consuming `input_path(job)`. This is an input foundation, not multiple editor/window support. It protects against ordinary source editing and detects snapshot tampering at launch; it is not a security boundary against an actor able to replace snapshot/job metadata after verification.
