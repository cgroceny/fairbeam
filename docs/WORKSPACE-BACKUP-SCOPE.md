# Design workspace identity

The server returns `backup_scope` on health, loaded/created DesignFile, save, rename and delete responses. The identity is `models-v1:<64 lowercase hex>`: SHA256 of a versioned domain plus the resolved, platform-normalized models directory. It identifies the actual design storage resource, independently of jobs/projects folders, server port, display names, design IDs or content hashes. Windows path case and canonical filesystem aliases share an identity; different models roots do not. No additional absolute path is exposed in this field.

Clients should capture scope from the same DesignFile response as the design/hash and retain it for that document, including backups, delayed callbacks, save and rename. Live health is not an authority for reassigning an already loaded draft. A directory move changes this path-based identity; this contract does not discover or migrate backups at the old location.

Save (`PUT /api/designs/<id>`), display rename and delete accept an optional `backup_scope` in the JSON body. A supplied value must exactly match the current server scope, including rejecting null/unknown values. A mismatch returns HTTP 409 with `workspace_error: "scope_mismatch"` before reading or changing the design; refresh/reopen the intended workspace. Existing hash/conflict, validation and active-job guards still apply after scope admission. Requests omitting the field retain legacy behavior and therefore have no workspace precondition. The scope is an identity/precondition, not an authorization secret.

The default editor captures this scope for its debounced backups and save requests. Home rename/Undo also retains the loaded file's scope. Backups are keyed by scope, design ID and saved base hash. Opening or editing a newer saved version does not overwrite an older draft. Only a matching scoped/base record is restored automatically; older-base and legacy records remain available as explicit downloads in the properties panel. They never replace the current design automatically. A successful save retires its matching old-base backup; intentional file deletion clears that workspace's scoped records. Unscoped legacy records are retained.

Last-opened state is workspace-scoped too. Startup captures health scope for lookup and checks the actual design response against it; live health never reassigns an open draft. A server without scope support cannot provide automatic recovery and the editor says so. Existing close/unsaved prompts still apply. These changes do not enable multiple editor windows. Linux/macOS normalization uses the same standard-library path operations; this has been tested on Windows, not natively on those platforms.
